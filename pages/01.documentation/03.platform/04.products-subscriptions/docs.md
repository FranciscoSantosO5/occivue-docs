# Products, Subscriptions and Access

The intended commercial model groups API access into **products or subscriptions**. A subscription is intended to determine which API products a user can access and which consumption policies apply.

Rate limits and quotas are intended to be **technically enforced** through the API-management layer rather than being alert-only controls.

The current knowledge base does not define final public product tiers, quota values or authentication mechanisms. Do not assume an API key, bearer token, OAuth flow or subscription key until the current API reference explicitly defines it.
